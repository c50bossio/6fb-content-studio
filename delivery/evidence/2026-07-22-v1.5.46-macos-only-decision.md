# v1.5.46 macOS-only release decision

Date: 2026-07-22

## Decision

The owner selected macOS arm64 as the only distribution platform for v1.5.46
and the near-term pilot. Windows distribution is deferred until Mac adoption
justifies the additional packaging, acceptance, support, and Authenticode work.

## Release contract

- `.github/workflows/release.yml` builds, signs, notarizes, stages, certifies,
  and publishes macOS arm64 only.
- The draft and public release must contain exactly four files:
  `6FB-Content-Studio-arm64.dmg`, `6FB-Content-Studio-arm64.zip`,
  `6FB-Content-Studio-arm64.zip.blockmap`, and `latest-mac.yml`.
- Publication still requires a staged downloaded-DMG check before promotion and
  an anonymous downloaded-DMG smoke after publication.
- `.github/workflows/release-windows.yml` remains manual and non-publishing so
  earlier Windows portability work is recoverable for a future product decision.
- Windows assets, Azure Artifact Signing, and Windows updater publication are
  not v1.5.46 gates.

## External-state boundary

- Draft Azure-signing pull request #29 was closed without merge after this
  decision. Its branch remains available as future reference.
- The signed-in Azure tenant showed zero subscriptions before this decision; no
  Artifact Signing account, GitHub signing environment, signing operation, tag,
  GitHub Release, or public v1.5.46 artifact was created by this workflow.
- Tagging and release publication remain separate explicit owner gates.

The anonymous public-manifest verifier was executed against historical release
v1.5.45. It rejected the release because its four Windows files made the asset
set eight instead of the required four. An invalid tag was also rejected before
network access. These are negative proofs that stale Windows assets and malformed
release inputs cannot silently satisfy the macOS-only gate.

The six workflow-referenced Apple/GitHub Actions secret names were present in
the repository settings; no secret values were read. `v1.5.46` remained absent
locally and on GitHub after merge and verification. No main-branch workflow was
configured to run for this merge, so the fresh exact-main local run is the
post-merge certification source. Commit
`e1fe4a9d94adb1aa59618a14dfd888257467fe5d` is the release-code anchor; the
exact tag target must still be resolved from live `origin/main` at approval time
so a later handoff-only commit cannot make the record self-referential.

This change does not modify renderer or application behavior, so the previously
clean 47-screen responsive matrix remains the applicable UI proof. No new UI
claim is based on the release-workflow change.
