## Candidate design

- GitHub OIDC through a pinned `azure/login` v3 commit; no PFX and no Azure
  client secret.
- Azure identifiers and issued signing data enter through the protected
  `windows-signing` environment.
- TrustedSigning PowerShell module pinned to `0.5.8`, SHA-256 file and timestamp
  digests, RFC3161 timestamp service, one file per request, 300-second service
  timeout, and Azure CLI credential only.
- The custom signer executes inside electron-builder's own signing lifecycle so
  internal files are signed before NSIS packaging and updater hashes are made.
- Every exact Windows EXE selected by electron-builder is immediately re-verified with SignTool `/pa /all /tw /v`
  plus PowerShell checks for valid Authenticode, timestamp, code-signing EKU,
  and the exact issued publisher DN. This closes TrustedSigning's warning-exit
  ambiguity.
- The workflow proves unsigned and byte-tampered negative fixtures are rejected.
- Staged-draft and anonymous-public certification downloads all four Windows
  assets, re-verifies both executable signatures, compares four SHA-256 build
  identities, and binds remote `latest.yml` top-level and sole `files` entry
  version/path/url/size/SHA-512 to the remotely downloaded signed installer.
- Network operations have three-attempt exponential backoff plus explicit
  metadata and asset timeouts.

## Required owner setup before dispatch

1. Approve the paid Azure Artifact Signing account and complete legal identity
   validation in Azure Portal.
2. Create a Public Trust certificate profile and obtain its exact publisher DN.
3. Create an Entra application and federated credential for issuer
   `https://token.actions.githubusercontent.com`, audience
   `api://AzureADTokenExchange`, and subject
   `repo:c50bossio/6fb-content-studio:environment:windows-signing`.
4. Grant only Artifact Signing Certificate Profile Signer at certificate-profile
   scope.
5. Explicitly create/protect GitHub environment `windows-signing`; configure the
   seven issued variables listed in the release-readiness checklist.
6. Obtain explicit approval before the first workflow dispatch because it
   performs paid signing and consumes signing quota.

Do not dispatch while the environment is absent: GitHub may automatically create
an unprotected environment. Merge, first paid signing run, tag creation, and
release publication remain separate approval gates.
